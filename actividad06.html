IPSEC VPN (SITE-TO-SITE)

Actividad 06 | Implementación de Túnel Seguro

01 Introducción Contextual al Tema

En esta actividad se realizó la implementación de una red utilizando una VPN (Virtual Private Network) con el protocolo IPSec. El objetivo principal fue conectar dos redes locales diferentes a través de una red pública (simulada por un router ISP), asegurando que la información viaje encriptada y segura.

Para lograr esto, se configuraron dos routers de borde (R1 y R2) para establecer un túnel por donde pasarán los datos de una PC a otra. Este mecanismo garantiza los principios de confidencialidad e integridad: si alguien intercepta el tráfico en el medio (Man-in-the-Middle), no podrá leerlo a menos que posea la clave privada correspondiente.

02 Desarrollo Técnico de la Actividad

1. Configuración Inicial y Enrutamiento

Se configuraron las interfaces y rutas estáticas apuntando al ISP para permitir la conectividad básica antes de establecer el túnel.

! Configuración Router ISP (Simulación de Internet)
ISP(config)# ip route 0.0.0.0 0.0.0.0 209.165.200.1

! Configuración R1 (Lado A)
R1(config)# ip route 0.0.0.0 0.0.0.0 209.165.100.2

! Configuración R2 (Lado B)
R2(config)# ip route 0.0.0.0 0.0.0.0 209.165.200.2

2. Habilitación de Licencia de Seguridad

Para utilizar las funciones criptográficas en los routers Cisco serie 1900, fue necesario activar el paquete de tecnología securityk9.

R1(config)# license boot module c1900 technology-package securityk9
ACCEPT? [yes/no]: yes
R1# reload

3. Definición de Tráfico Interesante (ACL)

Se configuraron Listas de Control de Acceso (ACL 100) para identificar qué tráfico debe ser encriptado y enviado por el túnel VPN.

R1(config)# access-list 100 permit ip 192.168.1.0 0.0.0.255 192.168.3.0 0.0.0.255
R2(config)# access-list 100 permit ip 192.168.3.0 0.0.0.255 192.168.1.0 0.0.0.255

4. Configuración de Políticas ISAKMP (Fase 1)

Se establecieron los parámetros para la negociación inicial: encriptación AES-256, autenticación Pre-Shared Key y grupo Diffie-Hellman 5.

R1(config)# crypto isakmp policy 10
R1(config-isakmp)# encryption aes 256
R1(config-isakmp)# authentication pre-share
R1(config-isakmp)# group 5
R1(config)# crypto isakmp key secretkey address 209.165.200.1

5. Configuración IPSec Transform-Set (Fase 2)

Se definió el conjunto de transformación para encriptar los datos del usuario.

R1(config)# crypto ipsec transform-set R1->R2 esp-aes 256 esp-sha-hmac

6. Creación y Aplicación del Mapa Criptográfico

Finalmente, se vinculan todas las configuraciones en un crypto map y se aplica a la interfaz de salida.

R1(config)# crypto map IPSEC-MAP 10 ipsec-isakmp
R1(config-crypto-map)# set peer 209.165.200.1
R1(config-crypto-map)# set transform-set R1->R2
R1(config-crypto-map)# match address 100
R1(config)# interface g0/0
R1(config-if)# crypto map IPSEC-MAP
*Jan 3 07:16:26.785: CRYPTO-6-ISAKMP ON OFF: ISAKMP is ON

04 Conclusiones y Resultados

La implementación de la VPN Site-to-Site fue exitosa. Como se muestra en la evidencia multimedia (Paso 8), la prueba de conectividad (PING) entre la PC-A (Red 192.168.1.0/24) y la PC-B (Red 192.168.3.0/24) fue correcta, lo que confirma que el túnel IPSec se estableció y el tráfico está fluyendo de manera encriptada a través de la red pública simulada.

Resultado Técnico: Se logró confidencialidad mediante AES-256 e integridad mediante SHA-HMAC, cumpliendo con los estándares de seguridad requeridos para interconectar sucursales.
